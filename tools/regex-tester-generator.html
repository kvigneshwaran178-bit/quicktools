What is a Regular Expression (Regex)?

A regular expression — often called a regex or regexp — is a sequence of characters that defines a search pattern. It is an incredibly powerful tool used by developers to search, extract, validate, and manipulate text strings. Regular expressions originated in the 1950s with mathematician Stephen Cole Kleene, who described them as a notation for a formal algebra of regular sets. They later became a core feature of the Unix command-line environment and are now built into virtually every programming language including JavaScript, Python, Java, Go, Rust, and PHP.

At their core, regexes describe patterns that strings either match or don't match. This binary nature makes them extremely useful for data validation tasks — checking that an email address looks like an email, or that a password meets complexity requirements — as well as for text processing pipelines, parsing log files, code search and refactoring, and extracting structured data from unstructured text.

How Regex Works

A regex engine reads a pattern character by character and attempts to align it with an input string. Different parts of a pattern have special meanings. For example, the dot character . matches any single character except a newline. The * quantifier means "zero or more of the preceding element." The caret ^ anchors the match to the start of the string, while the dollar sign $ anchors it to the end.

Most modern regex engines are NFA-based (Nondeterministic Finite Automaton), which means they explore multiple possible paths through the pattern simultaneously, backtracking when necessary. This gives them tremendous expressive power but also means certain patterns — particularly those with excessive backtracking — can run very slowly or even hang on certain inputs. Understanding how the engine works is key to writing efficient patterns.

Regex Flags Explained

Flags (also called modifiers) change how the regex engine interprets the pattern:

  • g — Global: Find all matches in the string rather than stopping after the first one.
  • i — Case Insensitive: Make letter comparisons case-insensitive, so a matches both a and A.
  • m — Multiline: Make ^ and $ match the start and end of each line rather than the entire string.
  • s — Dotall: Make the dot . character match newline characters as well as everything else.

Capture Groups

Capture groups, created with parentheses (), allow you to extract specific portions of a match. For example, the pattern (\d{4})-(\d{2})-(\d{2}) applied to 2026-06-06 would capture 2026 in group 1, 06 in group 2, and 06 in group 3. You can reference these captured values in replacement strings using $1, $2, etc. Named capture groups using the syntax (?<year>\d{4}) make the code even more readable and maintainable.

Common Regex Use Cases

  • Form Validation: Email addresses, phone numbers, postal codes, dates, credit card numbers
  • Data Extraction: Parsing log files, scraping HTML, reading CSV, extracting URLs from text
  • Search & Replace: Renaming variables in code, reformatting dates, cleaning up text
  • Tokenization: Breaking strings into tokens for parsers, lexers, or compilers
  • Security: Input sanitization, detecting injection patterns, filtering dangerous content

Regex Performance Tips

Writing efficient regex patterns is important, especially in high-traffic applications. Here are key practices to follow:

  • Be as specific as possible. Replace .* with more targeted patterns like \d{4} wherever possible.
  • Anchor your patterns with ^ and $ when you need to match the entire string — it dramatically reduces backtracking.
  • Avoid nested quantifiers like (a+)+ which can cause catastrophic backtracking (also called ReDoS).
  • Use non-capturing groups (?:...) instead of capturing groups when you don't need the captured value — it's slightly faster and reduces memory usage.
  • Pre-compile your regex patterns if you'll be using them repeatedly. In JavaScript, define const re = /pattern/flags; outside of loops.
  • Test your patterns against edge cases including empty strings, very long inputs, and strings that almost-but-don't-quite match.

Regex Best Practices

Beyond performance, clean and maintainable regex patterns are a professional craft. Always comment complex patterns using verbose mode where available. Use named capture groups for clarity. Break very long patterns into logical sections. Test your patterns thoroughly with both valid and invalid examples. When a regex becomes too complex, consider whether a simple string split or a proper parser might be a better tool for the job.

What is a capture group in regex?
+
A capture group is a part of your regex pattern enclosed in parentheses (). When the pattern matches, each capture group stores the portion of the string it matched independently. For example, with the pattern (\w+)@(\w+) applied to user@domain, group 1 captures user and group 2 captures domain. Our tool shows you capture groups from the first match in the Execution Console.
Why does my regex say "invalid"?
+
An invalid status means the JavaScript regex engine could not parse your pattern. Common causes include unbalanced parentheses ( without a closing ), an invalid escape sequence like \q, an empty character class [], or a quantifier without a preceding element like *abc. The error message shown below the pattern input explains the specific issue.
Can I use this for JavaScript regex?
+
Yes — this tool uses JavaScript's native RegExp engine, so any pattern that works here will work identically in your JavaScript code. Just wrap the pattern in forward slashes: /yourPattern/flags, or use the new RegExp('yourPattern', 'flags') constructor. The generated patterns are all JavaScript-compatible.
