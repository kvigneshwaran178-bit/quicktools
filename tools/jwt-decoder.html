JWT Architecture

Header · Payload · Signature

Every JWT is made of three Base64URL-encoded parts joined by dots

HEAD

Header

Defines the token type (typ) and signing algorithm (alg) used to generate the signature.

{ "alg": "HS256", "typ": "JWT" }
PAY

Payload

Contains the claims — statements about an entity (user) and additional metadata like expiry and issuer.

{ "sub": "user_123", "name": "Jane Doe", "iat": 1700000000, "exp": 1700086400 }
SIG

Signature

A cryptographic hash of the encoded header and payload. Used to verify the token hasn't been tampered with.

HMACSHA256( base64(header) + "." + base64(payload), secret_key )

Everything you need to know about JWT tokens and our decoder

A JSON Web Token (JWT) is a compact, URL-safe means of representing claims between two parties. It consists of three Base64URL-encoded parts: a Header, Payload, and Signature — separated by dots. JWTs are widely used for authentication and authorization in modern web applications and APIs.

Yes, completely. All decoding happens entirely in your browser using JavaScript. No token data is ever sent to our servers. The tool has zero network requests during decoding — your tokens stay 100% private on your device.

Paste your JWT token and click Decode. Our tool automatically reads the 'exp' claim from the payload and displays whether the token is still valid, expired, or expiring soon — along with a visual countdown timer showing time remaining or time since expiry.

Our decoder supports all JWT algorithms for inspection: HS256, HS384, HS512 (HMAC), RS256, RS384, RS512 (RSA), ES256, ES384, ES512 (ECDSA), and PS256, PS384, PS512 (RSA-PSS). For decoding and inspection, the algorithm doesn't affect parsing — only signature verification requires the secret key.

You can inspect, decode, and analyze any JWT token structure and claims. Full cryptographic signature verification requires the secret key or public key, which for security reasons you should never expose in a browser tool. Signature verification should always happen server-side in your application.
