What is Base64?

The encoding scheme every developer needs to know

🔤

Binary-to-Text

Base64 encodes binary data using only 64 printable ASCII characters — A–Z, a–z, 0–9, +, and /. It safely transports binary over text-only channels.

📦

Embed Anything

Embed images, fonts, or files directly in HTML, CSS, JSON, or XML without needing a separate file or URL — ideal for email templates and data URIs.

🔒

Not Encryption

Base64 is encoding — not encryption. Anyone can decode it without a key. Use AES or RSA for sensitive data. Use Base64 for safe transport.

⚖️

~33% Size Increase

Every 3 bytes of binary becomes 4 Base64 characters, increasing payload size by ~33%. This trade-off is acceptable for small assets.

⚡

Universal Support

Base64 is supported natively by every browser, operating system, and programming language — no external libraries needed.

🌐

URL-Safe Variant

The URL-safe Base64 variant replaces + with - and / with _, making it safe to use in URLs and filenames without percent-encoding.

How Base64 Works

The encoding algorithm step-by-step

Step 1 — Convert to binary: Take each character's ASCII value and write it as 8-bit binary. "Hi" → 01001000 01101001 Step 2 — Group into 6-bit chunks: Regroup the binary stream into 6-bit groups (padding with zeros to complete the last group). 010010 000110 1001xx → 010010 000110 100100 Step 3 — Map to Base64 alphabet: Each 6-bit value (0–63) maps to a character in the Base64 alphabet. 18 → S, 6 → G, 36 → k, padding → = Result: "Hi" → "SGk="

The padding character = is appended when the input length is not divisible by 3, ensuring the output length is always a multiple of 4 characters.

Everything you need to know about Base64

Base64 is a binary-to-text encoding scheme that represents binary data in an ASCII string format using 64 printable characters. It is widely used to encode binary data — such as images, files, and credentials — so it can be safely transmitted over text-based channels like email, HTTP headers, or embedded in HTML/CSS/JSON.
No. Base64 is purely an encoding scheme, not encryption. It does not provide any security or confidentiality — anyone can decode a Base64 string instantly without a key. If you need to secure data, use proper encryption algorithms like AES-256. Base64 is used for safe transport of binary data, not for protection.
The = padding characters appear when the input data length is not divisible by 3 bytes. Since Base64 works on 3-byte groups (producing 4 characters), one or two = characters are added to pad the output to a multiple of 4 characters. One = means 1 byte of padding; two == means 2 bytes of padding.
Base64 encoding increases the data size by approximately 33%. For every 3 bytes of input, it produces 4 characters of output. So a 100 KB image becomes approximately 133 KB when Base64 encoded. This overhead is a trade-off for compatibility with text-only environments.
